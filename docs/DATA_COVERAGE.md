# Data coverage

This file lists, one row per Jira data kind, what J2O does with it: whether it is migrated into a native OpenProject object, kept in a custom field or an archive, or not migrated. Each row names the OpenProject target, the condition or reason, and the component that implements it. The rows describe the default component sequence of `j2o migrate --profile full` unless a row names a switch or a separate command.

## Compared with the official OpenProject Jira importer

The facts about the official importer below come from its source code in opf/openproject: the tag v17.9.8, and the development branch `dev` at commit `17630b35c116` (read on 2026-11-22). Paths are relative to that repository.

| Topic | Official importer, v17.9.8 | Development branch `dev` | J2O |
|---|---|---|---|
| Jira key as work package identifier | Writes the key as `identifier` and its number as `sequence_number`, and adds aliases from key changes (`app/workers/import/jira_create_project_work_packages_job.rb:281-306`) | Writes the key's number as `sequence_number` ([`jira_create_project_work_packages_job.rb:399-401`](https://github.com/opf/openproject/blob/17630b35c116554be9fc9bc34a564d73fbc17ee0/app/workers/import/jira_create_project_work_packages_job.rb#L399-L401)) | Writes the same data when `migration.semantic_identifiers` is true ([ADR-011](adr/ADR-011-jira-keys-as-semantic-identifiers.md)) |
